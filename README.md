# 中大ポケット

中央大学の授業・教室・課題・シラバスをiPhoneの端末内に保存する、個人用のブラウザアプリです。公開するのはプログラムだけで、学生のデータ・パスワード・認証メールは含みません。

## 閉じても引き継ぐ保存

授業や課題を変更した時点でIndexedDBに保存し、保存が完了してから「保存済み」を表示します。次に開いたとき読み直します。前回の保存内容も端末内に残し、保存に失敗した場合は入力中の画面と最後の保存内容を保持します。既存の保存データは新しい形式へ移行し、読めないデータを空の状態で上書きしません。

設定から「保存データを保護」を実行できます。ブラウザが対応していれば永続ストレージを要求し、許可されたか表示します。ホーム画面に追加して、そのホーム画面版を授業データの保存先に統一してください。Safariタブとホーム画面版の保存領域は、同じ扱いになるとは限りません。端末変更や閲覧データの削除に備えてJSONバックアップも保存できます。

## GmailとCampusSquareのログイン補助

アプリの「取り込み」から「メール連携の設定」を開きます。iPhoneのSafari拡張機能 [Userscripts](https://apps.apple.com/jp/app/userscripts/id1463298887) に、`chuo-pocket-login.user.js` を一度インストールします。保存先は「このiPhone内」にし、GmailとCampusSquareでの実行を許可します。GmailはSafariの「デスクトップ用Webサイトを表示」で利用します。

### 補助が表示されないとき・最新版への更新

1. Safariで[最新版のログイン補助スクリプト](https://meta1529-dev.github.io/chuo-pocket/chuo-pocket-login.user.js)を開き、アドレス欄左端のページメニューからUserscriptsを開いて、同名のスクリプトを更新・上書きします。
2. Gmailのページへ戻り、同じページメニューからUserscriptsを一度開きます。**Enable Injection** と **Chuo Pocket Login** の両方をオンにしてください。スクリプト名を押すとオン・オフが切り替わるため、オンになったら繰り返し押さないでください。[Userscriptsの操作案内](https://github.com/quoid/userscripts#usage)
3. このサイトの実行許可は **「常に許可」（Always Allow）** にします。Userscriptsの画面を閉じ、Gmailを再読み込みしてください。画面下に **「中大ポケット v1.2.1」** が表示されれば更新完了です。CampusSquareも再読み込みします。

**Chuo Pocket Login が一覧にない場合**は、Userscriptsのフォルダボタンから全スクリプト一覧を確認してください。そこにもなければ、Userscriptsアプリで選んだ保存先にスクリプトが保存されているか確認し、上のリンクから再度追加します。

### 設定してログインする

1. Gmail設定に、大学の認証メールが届く大学配布アドレスを入力します。アカウント番号は、そのGmailをiPhoneのSafariで開いたURLが `/mail/u/0/` なら **0**、`/mail/u/1/` なら **1**です。
2. 「設定をこのiPhoneに保存」を押し、「設定を保存しました。」の表示を確認します。設定は次回も引き継ぎます。
3. 公式CampusSquareの認証メール送信画面で、大学の「送信」、または補助の「認証メールを送って続ける」を押します。
4. 大学の番号入力画面に進んだら、補助の「Gmailから番号を取得」を押し、開いたGmailで到着を待ちます。
5. 新しいメールが見つかったら、補助の「原文を開いて確認」を1回タップします。別タブに開いた原文で、補助が秒単位の受信時刻と大学の署名を確認します。
6. 確認完了の表示が出たらCampusSquareへ戻ります。新しい番号が公式フォームへ入力・送信されます。「この原文タブを閉じる」を押して通常のGmail画面へ戻ることもできます。

保存後に大学の「送信」を押すと、補助も開始します。送信前にGmailで過去メールを確認する往復は不要です。すでに認証メールを送信してからこの版を導入した場合は、今回の番号を大学の公式画面に手入力してください。次回、設定保存後に大学の「送信」を押すと補助を使えます。

保存できなかった場合は画面にエラーを表示します。Userscriptsがそのサイトで実行を許可されていることを確認し、もう一度保存してください。

原文のタブが開かない場合は、対象の認証メールでGmailの「その他のメッセージ オプション」→「原文を表示」をタップしてください。

Gmailアドレスとアカウント番号は拡張機能の端末内保存に残り、再起動後に引き継ぎます。認証の進行状況は期限付きの認証セッションとして別に保持し、同じ公式フォームであることを確認して再開します。Gmailを前面に開く操作、原文を開く1回のタップ、大学のタブへ戻る操作は必要です。iPhoneが閉じている間のバックグラウンド実行には依存しません。

JSONバックアップで保存・復元するのは、授業・教室・課題・シラバスのデータです。Gmail連携設定、認証セッション、Googleや大学のログイン状態は含みません。授業データを復元しても認証は再開しないため、ログインが必要な場合は公式画面から始めてください。

これは本人のメールに届いた番号を大学の正規の認証へ渡す仕組みです。大学・Googleの初回ログインやパスワード入力は公式画面で行います。大学やGoogleがログイン期限を切った場合、再認証が必要です。授業データや連携設定は、そのまま保持します。大学パスワードの収集・保存や、認証の省略は行いません。

送信元・件名・メールID・原文の受信時刻・Gmailの送信元と署名元を照合します。受信時刻は原文の受信記録から秒単位で確認し、対象のメールに結びつけます。古いメール、使用済みのメール、複数候補、違う画面、受信記録を確認できないメールでは入力を停止します。認証番号は入力まで短時間だけ拡張機能の保存領域に置き、使用時、または期限切れ後の再表示時に破棄します。認証メール本文や番号は公開サイトに送信せず、授業用の保存領域にも入れません。

## 授業データの取り込み

Safariでmanabaの曜日表示の時間割・未提出課題一覧、またはCampusSquareのシラバス詳細を開きます。「取り込み」→「設定手順を見る」の案内に従って、Safariの共有からページを読むショートカットを設定します。取得したデータを中大ポケットに貼り付け、保存前に項目を選びます。ショートカットのクリップボード設定は「ローカルのみ」にします。

授業の手動編集、複数の曜日・時限、課題の締切と完了状態、シラバス本文の保存、JSONバックアップの復元に対応しています。休講・教室変更の自動巡回は実装していません。最新の変更は公式MYスケジュールで確認してください。

## 確認状況

実際のmanabaの時間割・課題一覧・CampusSquareのシラバスと認証フォーム・Gmailの認証通知の構造を確認しています。架空HTMLで認証メールの選別、署名の照合、公式フォームへの送信、ページ再起動後の復元、番号の一度だけの消費を検証しています。

iPhone実機でのUserscriptsの許可・原文を開くタップ・タブ切替・番号入力からログイン完了までの一連の動作は未確認です。プログラムの検証成功だけで、スマホ単独での動作が完了したとは扱っていません。

## 配信ファイル

ローカルの `dist/` がアプリ本体です。GitHubでは同じ内容を `docs/` に置き、GitHub Pagesの `main` ブランチ・`/docs` から配信します。`data.js` が端末保存、`app.js` が画面、`chuo-pocket-login.user.js` がSafariのメール連携を担当します。外部の分析サービス・アプリサーバーは使用しません。
